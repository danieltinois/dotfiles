# How a command gets checked

Every time an agent wants to read a file, edit one or run a shell command, the request passes through three layers. The first two read text and can be fooled; the third is the operating system saying no.

  agent wants to: cat .env, git push --force, edit eslint config
                               |
                               v
  +------------------------------------------------------------+
  | 1  guard.sh          PreToolUse hook, reads the request    |
  |    stops secrets, force push, --no-verify, AI attribution, |
  |    rm -rf on / or ~, edits to an existing lint config      |
  +------------------------------------------------------------+
                               | passes
                               v
  +------------------------------------------------------------+
  | 2  permissions       allow / ask / deny in settings.json   |
  |    read-only git, rg, tests: allowed without asking        |
  |    git push, git clean, reset --hard, rm -rf: ask me first |
  +------------------------------------------------------------+
                               | allowed
                               v
  +------------------------------------------------------------+
  | 3  sandbox          macOS Seatbelt, enforced by the kernel |
  |    write: project folder + temp    read: no ~/.ssh, ~/.aws |
  |    network: GitHub, npm, PyPI, Azure DevOps                |
  +------------------------------------------------------------+
                               |
                               v
                         command runs  then format-on-edit.sh
                                       formats any edited file

Where things are linked

  • ai/AGENTS.md is both ~/.claude/CLAUDE.md and ~/.codex/AGENTS.md. One file, two agents, same rules. A repo's own CLAUDE.md or AGENTS.md always wins over it.
  • ai/claude/scripts/ is ~/.claude/scripts, which the hooks in ~/.claude/settings.json point at.
  • ~/.claude/settings.json is not a symlink, because Claude Code rewrites it. The sandbox part is kept as a copy in ai/claude/sandbox.json.

# The hooks

Hooks are scripts Claude Code runs around each tool call. They are fast and specific, but they only see text, so they are the first filter, not the wall.

guard.sh, before every call

Runs before Bash, Read, Grep, Glob, Edit, Write, MultiEdit and NotebookEdit. If it blocks, the agent sees why and is told to ask me to do it by hand.

  • cat .envblockedreading a secret
  • git push --forceblockedforced push, includes +refspec
  • git commit --no-verifyblockedskips hooks and lint
  • rm -rf ~blockedroot or home
  • edit analysis_options.yamlblockedfix the code, not the rule
  • create a new eslint.config.jsoknew configs are fine
  • glob ".e*"blockedcould match a .env file
  • glob "**/*.dart"okcan't form a secret name

Commit messages and PR bodies with an AI Co-Authored-By or a "Generated with" footer are blocked too: everything goes out under my name. For globs it expands braces and fails closed, so ? or [ in a file name is refused. One known gap: *.test.* could match .env.test.local, which the sandbox covers.

format-on-edit.sh, after every edit

Formats the file with the project's own formatter: dart format, prettier, ruff and friends. It only looks up to the repo root. Tools the repo chooses (prettier from node_modules, the Flutter SDK from .fvmrc) only run for repos inside a trusted folder, so a repo I cloned just to read can't run anything through it.

statusline.sh, always on screen

Opus 5.5 · dotfiles ·  main* ◆
██████░░░░ 62% ctx · 5h 31% · +120 -14
  • Line one: model, folder, branch. * means uncommitted changes; ◆ means the repo has a graphify graph.
  • Line two: context used, the 5-hour limit and lines added or removed. Green under 50%, yellow under 80%, red after.
  • ? instead of * means the repo defines its own git filters, so the status line skipped git status on purpose.

# The sandbox

The real wall. Every Bash command runs inside macOS Seatbelt and the kernel refuses what is outside the rules, whatever the command looks like. It lives in the sandbox block of ~/.claude/settings.json, copied in ai/claude/sandbox.json.

write
The project folder, the temp dir and ~/.npm/_cacache. Nothing that runs later outside the sandbox: not ~/.cache (my prompt loads a script from there), not the Flutter SDK, pnpm or anything on PATH.
read
Everything except credentials: ~/.ssh, ~/.aws, ~/.gnupg, ~/.docker, ~/.kube, ~/.azure, gcloud, .npmrc, .netrc, git, gh, Gradle and pub credentials, plus every .env and key file.
network
Through a proxy that knows GitHub, npm, PyPI and Azure DevOps. Other hosts need approval.
outside
docker and gh run unsandboxed, as the docs recommend. Flutter and pnpm fail inside and ask to run outside, one command at a time.
limits
Git credentials in the macOS Keychain are still reachable (push over HTTPS needs them). Hooks, MCP servers and the status line run outside the sandbox.

# Skills

Small instruction files the agent loads when a request matches. I trigger them in Portuguese or English.

save-session
Say "salva a sessão" and it writes a handoff to .claude/sessions/: what worked with evidence, what failed and why, and the exact next step. "retoma a sessão" picks it up in a clean session. Better than a long compacted one.
codex-review
"revisa com o codex" sends the current diff to Codex for a second opinion before a commit or PR.
claude-review
The same, the other way around: Codex asks Claude.

# Set up a new machine

Paths assume the repo is cloned to ~/development/dotfiles. Change D if you put it somewhere else.

  1. Clone and install the apps.

    $ git clone https://github.com/danieltinois/dotfiles ~/development/dotfiles
$ brew bundle --file ~/development/dotfiles/Brewfile

  2. Apply the macOS defaults. Safe to run again; some need a logout.

    $ bash ~/development/dotfiles/macos.sh

  3. Link the agent rules, hooks, skills and terminal config.

    $ D=~/development/dotfiles
$ ln -sfn $D/ai/AGENTS.md ~/.claude/CLAUDE.md
$ ln -sfn $D/ai/AGENTS.md ~/.codex/AGENTS.md
$ ln -sfn $D/ai/claude/scripts ~/.claude/scripts
$ ln -sfn $D/ai/skills/codex-review ~/.claude/skills/codex-review
$ ln -sfn $D/ai/skills/claude-review ~/.codex/skills/claude-review
$ ln -sfn $D/ai/skills/save-session ~/.claude/skills/save-session
$ ln -sfn $D/ai/skills/save-session ~/.codex/skills/save-session
$ ln -sfn $D/ghostty.config ~/.config/ghostty/config

  4. Open ~/.claude/settings.json, paste the sandbox block from ai/claude/sandbox.json, and register the hooks: ~/.claude/scripts/guard.sh as PreToolUse, format-on-edit.sh as PostToolUse and statusline.sh as the status line.

# When something gets in the way

guard.sh blocked something I really meant to do

That's the design: the agent can't override it. Run the command yourself in a terminal. If it keeps happening for a safe pattern, change the rule in ai/claude/scripts/guard.sh and check that the dangerous cases are still blocked before committing.

Flutter or pnpm fails inside the sandbox

They write to the SDK and the shared store, which the sandbox refuses. Approve running that command outside when Claude asks. To stop being asked, add "fvm *", "flutter *", "dart *" or "pnpm *" to excludedCommands; they then run with full access.

A command needs a site that isn't on the network list

Add the domain to sandbox.network.allowedDomains in ~/.claude/settings.json, then copy the block back to ai/claude/sandbox.json so the repo matches:

$ jq '{sandbox: .sandbox}' ~/.claude/settings.json > ~/development/dotfiles/ai/claude/sandbox.json
Files aren't formatted in a repo I just cloned

It's outside the trusted folders, so its own prettier or SDK won't run. If you trust it, add its parent folder, one per line, to ~/.config/claude-hooks/trusted-roots. Without that file only ~/development is trusted.

The status line shows ? next to the branch

The repo defines git clean/smudge filters in its own config, and git status would run them. The status line skips it on purpose. Check git config --show-scope --get-regexp '^filter\.' if you want to know which.

The session got long and the agent is losing the thread

Say "salva a sessão", start a new session and say "retoma a sessão". The handoff keeps what failed, so the next session doesn't try it again.

A git command fails with "unable to unlink" on AGENTS.md

The sandbox won't let shell commands overwrite agent instruction files, so a git switch or merge that touches ai/AGENTS.md fails halfway. Run that git command yourself in a terminal.
