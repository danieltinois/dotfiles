#How a command gets checkedComo um comando é checado

Every time an agent wants to read a file, edit one or run a shell command, the request passes through three layers. The first two read text and can be fooled; the third is the operating system saying no.

Toda vez que um agente quer ler um arquivo, editar um ou rodar um comando, o pedido passa por três camadas. As duas primeiras leem texto e podem ser enganadas; a terceira é o próprio sistema operacional dizendo não.

Where things are linkedOnde cada coisa é linkada

  • ai/AGENTS.md is both ~/.claude/CLAUDE.md and ~/.codex/AGENTS.md. One file, two agents, same rules. A repo's own CLAUDE.md or AGENTS.md always wins over it.
  • ai/claude/scripts/ is ~/.claude/scripts, which the hooks in ~/.claude/settings.json point at.
  • ~/.claude/settings.json is not a symlink, because Claude Code rewrites it. The sandbox part is kept as a copy in ai/claude/sandbox.json.
  • ai/AGENTS.md é ao mesmo tempo ~/.claude/CLAUDE.md e ~/.codex/AGENTS.md. Um arquivo, dois agentes, as mesmas regras. O CLAUDE.md ou AGENTS.md do próprio repo sempre ganha dele.
  • ai/claude/scripts/ é ~/.claude/scripts, para onde apontam os hooks do ~/.claude/settings.json.
  • ~/.claude/settings.json não é symlink porque o Claude Code reescreve esse arquivo. A parte do sandbox fica copiada em ai/claude/sandbox.json.

#The hooksOs hooks

Hooks are scripts Claude Code runs around each tool call. They are fast and specific, but they only see text, so they are the first filter, not the wall.

Hooks são scripts que o Claude Code roda em volta de cada chamada de ferramenta. São rápidos e específicos, mas só enxergam texto: são o primeiro filtro, não o muro.

guard.sh, before every callguard.sh, antes de cada chamada

Runs before Bash, Read, Grep, Glob, Edit, Write, MultiEdit and NotebookEdit. If it blocks, the agent sees why and is told to ask me to do it by hand.

Roda antes de Bash, Read, Grep, Glob, Edit, Write, MultiEdit e NotebookEdit. Quando bloqueia, o agente vê o motivo e é orientado a me pedir para fazer na mão.

Commit messages and PR bodies with an AI Co-Authored-By or a "Generated with" footer are blocked too: everything goes out under my name. For globs it expands braces and fails closed, so ? or [ in a file name is refused. One known gap: *.test.* could match .env.test.local, which the sandbox covers.

Mensagens de commit e descrições de PR com Co-Authored-By de IA ou rodapé "Generated with" também são barradas: tudo sai só no meu nome. Nos globs ele expande chaves e falha fechado, então ? ou [ no nome do arquivo é recusado. Uma brecha conhecida: *.test.* poderia achar .env.test.local, e quem cobre isso é o sandbox.

format-on-edit.sh, after every editformat-on-edit.sh, depois de cada edição

Formats the file with the project's own formatter: dart format, prettier or ruff. It only looks up to the repo root. Tools the repo chooses (prettier from node_modules, the Flutter SDK from .fvmrc) only run for repos inside a trusted folder, so a repo I cloned just to read can't run anything through it.

Formata o arquivo com o formatador do próprio projeto: dart format, prettier ou ruff. Só procura até a raiz do repo. Ferramentas escolhidas pelo repo (o prettier do node_modules, o SDK do Flutter pelo .fvmrc) só rodam em repos dentro de uma pasta confiável, então um repo que clonei só para ler não consegue rodar nada por ali.

#The sandboxO sandbox

The real wall. Every Bash command runs inside macOS Seatbelt and the kernel refuses what is outside the rules, whatever the command looks like. It lives in the sandbox block of ~/.claude/settings.json, copied in ai/claude/sandbox.json.

O muro de verdade. Todo comando Bash roda dentro do Seatbelt do macOS e o kernel recusa o que estiver fora das regras, não importa a cara do comando. Ele fica no bloco sandbox do ~/.claude/settings.json, copiado em ai/claude/sandbox.json.

╔══════════════════════ macOS Seatbelt ══════════════════════╗
║                                                            ║
║  ┌─ read + write ──────────┐ ┌─ read only ──────────────┐  ║
║  │ the project folder      │ │ the rest of the disk     │  ║
║  │ $TMPDIR                 │ │ ~/.zshrc, ~/fvm          │  ║
║  │ ~/.npm/_cacache         │ │ ~/.cache, PATH dirs      │  ║
║  └─────────────────────────┘ └──────────────────────────┘  ║
║                                                            ║
║  $ command ──▶ proxy ──▶ GitHub npm PyPI Azure             ║
║                  └──▶ any other host: ask or block         ║
╚════════════════════════════════════════════════════════════╝

  nunca legíveis, nem por um script:

  ✗ ~/.kube    ✗ ~/.azure   ✗ gcloud     ✗ ~/.npmrc

why so few writes
Anything a sandboxed command writes and something later runs outside the sandbox would be an escape. That's why ~/.cache (my prompt loads a script from there), the Flutter SDK, pnpm and anything on PATH are left out.
runs outside
docker and gh run unsandboxed, as the docs recommend. Flutter and pnpm fail inside and ask to run outside, one command at a time.
known limits
Git credentials in the macOS Keychain are still reachable (push over HTTPS needs them). Hooks, MCP servers and the status line run outside the sandbox. Outside manual mode, a new host can be approved by the auto-mode classifier unless strictAllowlist is on.
por que grava tão pouco
Qualquer coisa que um comando no sandbox grave e que depois rode fora dele vira uma fuga. Por isso ficam de fora o ~/.cache (meu prompt carrega um script de lá), o SDK do Flutter, o pnpm e tudo que está no PATH.
roda fora
docker e gh rodam sem sandbox, como a documentação recomenda. Flutter e pnpm falham lá dentro e pedem para rodar fora, um comando de cada vez.
limites conhecidos
As credenciais git no Keychain do macOS continuam acessíveis (o push por HTTPS precisa delas). Hooks, servidores MCP e a status line rodam fora do sandbox. Fora do modo manual, um host novo pode ser aprovado pelo classificador do auto mode, a menos que o strictAllowlist esteja ligado.

#Skills

Small instruction files the agent loads when a request matches. They trigger in Portuguese or English.

Arquivos curtos de instrução que o agente carrega quando o pedido bate. Disparam em português ou inglês.

save-session
Say "save the session" and it writes a handoff to .claude/sessions/: what worked with evidence, what failed and why, and the exact next step. "resume the session" picks it up in a clean session, which beats a long compacted one.
codex-review
"review with codex" sends the current diff to Codex for a second opinion before a commit or PR.
claude-review
The same, the other way around: Codex asks Claude.
save-session
Fale "salva a sessão" e ela escreve um handoff em .claude/sessions/: o que funcionou com evidência, o que falhou e por quê, e o próximo passo exato. "retoma a sessão" continua numa sessão limpa, o que rende mais que uma longa e compactada.
codex-review
"revisa com o codex" manda o diff atual para o Codex dar uma segunda opinião antes do commit ou do PR.
claude-review
O mesmo, ao contrário: o Codex pede ao Claude.

#When something gets in the wayQuando alguma coisa trava

guard.sh blocked something I really meant to doO guard.sh barrou algo que eu queria mesmo fazer

That's the design: the agent can't override it. Run the command yourself in a terminal. If it keeps happening for a safe pattern, change the rule in ai/claude/scripts/guard.sh and check that the dangerous cases are still blocked before committing.

É de propósito: o agente não consegue passar por cima. Rode o comando você mesmo num terminal. Se acontecer sempre com um padrão seguro, ajuste a regra em ai/claude/scripts/guard.sh e confira que os casos perigosos continuam barrados antes de commitar.

Flutter or pnpm fails inside the sandboxFlutter ou pnpm falha dentro do sandbox

They write to the SDK and the shared store, which the sandbox refuses. Approve running that command outside when Claude asks. To stop being asked, add "fvm *", "flutter *", "dart *" or "pnpm *" to excludedCommands; they then run with full access.

Eles gravam no SDK e no store compartilhado, e o sandbox recusa. Aprove rodar aquele comando fora quando o Claude pedir. Para não ser mais perguntado, adicione "fvm *", "flutter *", "dart *" ou "pnpm *" em excludedCommands; aí eles rodam com acesso total.

A command needs a site that isn't on the network listUm comando precisa de um site fora da lista de rede

Add the domain to sandbox.network.allowedDomains in ~/.claude/settings.json, then copy the block back to the repo so both match:

Adicione o domínio em sandbox.network.allowedDomains no ~/.claude/settings.json e copie o bloco de volta para o repo, para os dois ficarem iguais:

$ jq '{sandbox: .sandbox}' ~/.claude/settings.json > ~/development/dotfiles/ai/claude/sandbox.json
Files aren't formatted in a repo I just clonedOs arquivos não são formatados num repo que acabei de clonar

It's outside the trusted folders, so its own prettier or SDK won't run. If you trust it, add its parent folder, one per line, to ~/.config/claude-hooks/trusted-roots. Without that file only ~/development is trusted.

Ele está fora das pastas confiáveis, então o prettier ou o SDK dele não rodam. Se confiar nele, adicione a pasta-mãe, uma por linha, em ~/.config/claude-hooks/trusted-roots. Sem esse arquivo, só ~/development é confiável.

The status line shows ? next to the branchA status line mostra ? ao lado da branch

The repo defines git clean/smudge filters in its own config, and git status would run them. The status line skips it on purpose. To see which ones:

O repo define filtros git clean/smudge na própria config, e o git status rodaria esses filtros. A status line pula de propósito. Para ver quais são:

$ git config --show-scope --get-regexp '^filter\.'
The session got long and the agent is losing the threadA sessão ficou longa e o agente está se perdendo

Say "save the session", start a new session and say "resume the session". The handoff keeps what failed, so the next session doesn't try it again.

Fale "salva a sessão", abra uma sessão nova e fale "retoma a sessão". O handoff guarda o que falhou, então a próxima sessão não tenta de novo.

A git command fails with "unable to unlink" on AGENTS.mdUm comando git falha com "unable to unlink" no AGENTS.md

The sandbox won't let shell commands overwrite agent instruction files, so a git switch or merge that touches ai/AGENTS.md fails halfway. Run that git command yourself in a terminal.

O sandbox não deixa comandos de shell sobrescreverem arquivos de instrução de agente, então um git switch ou merge que mexe no ai/AGENTS.md falha no meio. Rode esse comando git você mesmo num terminal.
